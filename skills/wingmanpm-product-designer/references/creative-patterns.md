# Creative patterns that serve the task

Use for exploration, a new surface, or a request for a stronger signature. Skip
this library for a precise repair. These are starting hypotheses, not templates,
aesthetic rules, or claims that one pattern always wins.

Run `patterns "<object, decision, constraint>" --limit 3 --json`. Read those compact
records only. Each includes a useful condition, structure, signature, mobile
translation, and risk. Use `patterns --id <id>` to revisit a selected record.
Search ranks relevant words; the agent must judge suitability against the brief.

## Diverge cheaply, develop deeply

1. Ground the brief in one sentence: who must decide or do what, using which
   evidence, under which constraint. Identify the existing brand constants.
2. Sketch four one-line hypotheses internally. Include one from the pattern
   search, one inversion of the obvious structure, and one from the product's
   own objects or relationships. This is a small thought pass, not four builds.
3. Select two that differ on at least two useful dimensions: dominant object,
   information order, detail reveal, or action sequence. Record the user benefit
   and cost of each. Color, radius, font, and panel count alone are not enough.
4. Build the smallest slice that reveals the difference, at equal fidelity and
   with identical facts. Give each one signature move and one coherent system
   for type, spacing, color, controls, and states. Keep supporting detail quiet.
5. Show the primary task and a hard state at desktop and mobile widths. Apply
   [minimum craft](craft.md) to both. Recommend based on observed task clarity,
   detail quality, and risks; show the tradeoff so the user can disagree.

A signature can be a clear change view, a source anchor, a meaningful spatial
relationship, a useful live preview, a memorable product scene, or a precise
transition. It does not need more decoration, more panels, or more motion.
Motion must explain a state change and retain a reduced-motion path.

## Avoid convergence and token waste

Do not always produce a list and a split pane. Ask whether the second option
changes how the task is understood or performed. If both have the same reading
and action order, revise one concept before writing more code. Conversely, do
not force novelty when an established pattern best serves the task.

Share data, copy, assets, and brand constants across variants. Keep discarded
ideas to one line; save full reasoning only for a consequential decision. Load
one active pattern plus at most one supporting pattern. Spend remaining effort
on execution: typography, alignment, long content, feedback, keyboard use, and
mobile translation. Stop after the agreed comparison; don't generate endless
variants to chase a subjective score.
